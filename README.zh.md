# Duck Tracks

[English](README.md) · [한국어](README.ko.md) · **简体中文**

在 **Escape from Duckov** 中，走过的地方会留下脚印。不是按固定距离铺设，而是在脚真正着地的瞬间压印，形状取自角色当前穿着的那只脚。

## 功能

**在真正落地的瞬间压印** — 每帧读取脚部骨骼的高度，只在着地的那一刻压印。站着不动不会留下，奔跑时脚印会拉开，左右正确交替——因为那本来就是左脚和右脚。

**用你当前穿着的脚型** — 默认脚印是角色所穿之脚的轮廓，直接从模型上提取。换鞋后脚印随之改变，大小也取自实际的脚。

**内置脚印 21 种** — 鸭子、熊、猫、狗、狼、鸟、鸡、马蹄、牛蹄、鹿、赤脚、靴子、运动鞋、兔子、蜥蜴、青蛙、恐龙、肉垫、爱心、星星、轮胎纹。

**放入自己的图片** — 把 PNG 放进文件夹就会出现在选择器中。用`重新扫描文件夹`即可生效，无需重启。

**自己绘制** — 手动涂格子来制作。烘焙时会修整边缘，所以 24 格也能画得很平滑。

**随机脚印** — 不是随机色块。参数取自肉垫、脚趾、爪子、蹼、蹄裂构成的语法，因此出来的一定是脚的形状。

**颜色** — 刚压印时和消退时两种颜色，可用饱和度／明度方块与色相条选取，或直接输入 HEX / R,G,B。可以像泥土那样覆盖地面，也可以在暗处发光并调节强度。

**闪烁与变色** — 亮度脉动、色相旋转。两者都以每个脚印各自的年龄来计算，因此效果是沿着足迹流动的波浪，而不是整个画面一起闪。

**落脚颗粒** — 着地时颗粒溅起，留在地上的脚印也会缓缓飘出颗粒。两者共用形状、颜色和寿命，看起来像同一族。

**持续时间** — 以秒为单位设定，或开启`永久保留`让脚印不再消失，此时数量上限也会解除。

全部设置位于暂停菜单的`脚印设置`中，支持简体中文、繁體中文、English、한국어。

## 实现要点

这款游戏的四个特点决定了实现方式。

| 问题 | 代码的做法 |
|---|---|
| `CharacterModel` 提供了手、护甲、头盔、脸、背包、近战武器的插槽，**却没有脚的插槽** | 遍历模型层级，按名称查找 `Foot.L` / `Foot.R` 骨骼。脚的朝向取自「骨骼→趾尖」向量，而非骨骼的局部轴——局部轴取决于绑定者的习惯，不可依赖 |
| 脚部网格 `isReadable = false`，CPU 无法读取顶点 | 轮廓是**画出来的，不是算出来的**。把网格放到地图下方很远处，用正交相机自上而下拍一张再读回。GPU 本来就不需要 CPU 访问 |
| `colorOverLifetime` 渐变最多只有 8 个关键帧，长寿命下无法表达流动的脉冲，无限寿命下则完全不行 | 逐个写入颗粒颜色，依据**每个颗粒自己的年龄**。压印时刻不同，相位差便自然产生——这正是波浪沿足迹流动的原因 |
| 把「永久」寿命设为 10⁶ 秒后，上述年龄运算悄悄冻结 | 在 10⁶ 处 float 的最小间隔是 0.0625 秒，比一帧还大，`remainingLifetime -= deltaTime` 根本不生效，所有年龄恒为 0。改为 36 000 秒，那里间隔是 0.004 秒，一帧有四倍余量 |

还有两点。脚印用的是 `HorizontalBillboard` 而非常见的面向相机的公告板——正是这一行让脚印在俯视视角下平躺在地面，而不是像卡片一样立起来。另外，当渲染器报告 `isVisible == false` 时会完全跳过闪烁计算，因为读取并重写所有存活颗粒的开销与数量成正比，而无限寿命下地图上可能散布着数千个。

## 构建

需要 .NET SDK 和游戏本体。

```
cp Local.props.example Local.props     # 将 SteamFolder 指向你的安装目录
dotnet build -c Release
```

Ducky SDK 会把构建结果放入游戏的 `Mods` 文件夹。`0Harmony.dll` 在那之后单独复制，因为 SDK 会先清空并重建模组文件夹。版本为何必须完全一致、为何不能取引用程序集，都写在 `DuckTracks.csproj` 的注释里。

Harmony 只用于一件事：让设置窗口打开期间游戏表现为暂停状态。除此之外本模组不拦截任何内容，只是每帧读取角色位置。

# Duck Tracks

[English](README.md) · **한국어** · [简体中文](README.zh.md)

**Escape from Duckov**에서 지나간 자리에 발자국이 남습니다. 일정 거리마다 찍는 방식이 아니라, 발이 실제로 바닥에 닿는 순간에 지금 신고 있는 그 발 모양으로 찍힙니다.

## 기능

**실제로 디딜 때 찍힘** — 발 뼈의 높이를 매 프레임 보고 바닥에 닿는 전이 순간에만 찍습니다. 제자리에 서 있으면 남지 않고, 달리면 보폭만큼 벌어지고, 좌우가 번갈아 나옵니다. 실제로 왼발과 오른발이니까요.

**지금 신고 있는 그 발 모양** — 기본 자국은 캐릭터가 신고 있는 발의 실루엣입니다. 모델에서 직접 떠 옵니다. 신발을 갈아 신으면 자국도 따라 바뀌고, 크기도 실제 발에서 잽니다.

**내장 발자국 21종** — 오리 · 곰 · 고양이 · 개 · 늑대 · 새 · 닭 · 말굽 · 소굽 · 사슴 · 맨발 · 부츠 · 운동화 · 토끼 · 도마뱀 · 개구리 · 공룡 · 발바닥 · 하트 · 별 · 타이어.

**그림 넣기** — 폴더에 PNG를 넣으면 목록에 나타납니다. `폴더 다시 읽기`로 게임 재시작 없이 반영됩니다.

**직접 그리기** — 격자를 손으로 칠해 만듭니다. 구울 때 가장자리를 다듬기 때문에 24칸으로도 매끄럽게 나옵니다.

**무작위 발자국** — 아무 얼룩이 아닙니다. 패드 · 발가락 · 발톱 · 물갈퀴 · 갈라짐의 문법에서 매개변수를 뽑기 때문에 나오는 것이 전부 발 모양입니다.

**색** — 찍힌 직후와 사라질 때 두 색을. 채도·명도 사각형과 색조 막대로 고르거나 HEX / R,G,B를 직접 넣습니다. 흙처럼 바닥을 덮을지, 어두운 곳에서 빛나게 할지 고르고 세기도 조절합니다.

**깜박임과 색 순환** — 밝기가 맥동하고 색조가 돌아갑니다. 둘 다 자국 하나하나의 나이로 계산하기 때문에, 화면 전체가 껌뻑이는 게 아니라 걸어온 길을 따라 물결이 흘러갑니다.

**걸음 알갱이** — 디딜 때 알갱이가 튀어오르고, 바닥에 남은 자국에서 은은하게 떠오릅니다. 모양·색·수명을 둘이 같이 써서 한 가족으로 읽힙니다.

**지속 시간** — 초 단위로 정하거나, `계속 남기기`로 사라지지 않게 합니다. 이때는 개수 제한도 풀립니다.

전부 일시정지 메뉴의 `발자국 설정`에 있습니다. 한국어 · English · 简体中文 · 繁體中文.

## 어떻게 만들었나

이 게임의 네 가지 사정이 구현을 결정했습니다.

| 문제 | 코드가 한 일 |
|---|---|
| `CharacterModel`이 손·방어구·헬멧·얼굴·가방·근접무기 소켓은 주는데 **발 소켓은 없음** | 모델 계층을 훑어 `Foot.L` / `Foot.R` 뼈를 이름으로 찾습니다. 발이 향한 쪽은 뼈의 로컬 축이 아니라 뼈→발끝 벡터로 구합니다 — 로컬 축은 리그를 만든 쪽 관례라 믿을 수 없습니다 |
| 발 메시가 `isReadable = false`라 CPU에서 정점을 못 읽음 | 실루엣을 **계산하지 않고 그립니다**. 메시를 맵 훨씬 아래에 놓고 직교 카메라로 위에서 한 장 찍어 되읽습니다. GPU는 애초에 CPU 접근이 필요 없었습니다 |
| `colorOverLifetime` 그라디언트는 키가 최대 8개라, 긴 수명에서는 물결을 표현할 수 없고 무한 수명에서는 아예 불가능 | 알갱이 색을 **각자의 나이로** 하나씩 씁니다. 찍힌 시각이 다르니 위상 차이가 공짜로 생기고, 그게 물결이 길을 따라 흘러가는 이유입니다 |
| "무한" 수명을 10⁶초로 잡았더니 그 나이 계산이 조용히 얼어붙음 | 10⁶에서 float의 최소 간격은 0.0625초 — 한 프레임보다 큽니다. `remainingLifetime -= deltaTime`이 아예 반영되지 않아 모든 나이가 0이었습니다. 36 000초로 낮췄고, 거기선 간격이 0.004초라 한 프레임이 네 배 여유로 들어갑니다 |

작은 것 둘. 자국은 흔한 카메라 지향 빌보드가 아니라 `HorizontalBillboard`입니다 — 탑다운 시점에서 자국이 카드처럼 서지 않고 바닥에 눕게 하는 것이 이 한 줄입니다. 그리고 렌더러가 `isVisible == false`를 내면 깜박임 계산을 통째로 건너뜁니다. 살아 있는 알갱이를 전부 읽고 다시 쓰는 일이라 개수에 정비례하는데, 무한 지속이면 맵 전체에 수천 개가 깔릴 수 있습니다.

## 빌드

.NET SDK와 게임이 필요합니다.

```
cp Local.props.example Local.props     # SteamFolder를 설치 경로로
dotnet build -c Release
```

Ducky SDK가 빌드 결과를 게임 `Mods` 폴더에 넣습니다. `0Harmony.dll`은 그 뒤에 따로 복사합니다 — SDK가 모드 폴더를 먼저 지우고 다시 만들기 때문입니다. 버전이 왜 정확히 맞아야 하는지, 참조 전용 어셈블리를 집으면 왜 안 되는지는 `DuckTracks.csproj`의 주석에 적어 두었습니다.

Harmony는 딱 하나에 씁니다. 설정 창이 떠 있는 동안 게임이 정지 상태인 것처럼 굴게 하는 것. 그 밖에는 아무것도 가로채지 않고 매 프레임 캐릭터 위치를 읽을 뿐입니다.
